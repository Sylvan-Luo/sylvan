# 工具箱规矩

用户会陆续让各个会话做很多可复用的工具（研究类、实用类，比如微信自动回复、PDF 标准模板）。
目标：任何一个会话做出来的工具，其他会话都能找到、会用、能接着改。

## 先查再做
1. 先读 `~/tools/README.md` 的登记表，看是不是已经有了（包括 ~/.claude/skills/ 下各工具的技能说明）。
2. 已经有的：直接用；要改就在原目录里改，不要另起一份。

## 新建一个工具
1. 名字用英文小写加连字符（例：`pdf-report`、`wechat-reply`）。
2. 代码放 `~/tools/<名字>/`，从 `~/tools/_template/README.md` 抄一份说明改写。
   大文件（数据、模型、导出结果）放 `~/data/tools/<名字>/`，代码里用路径引用。
3. 写技能说明 `~/.claude/skills/<名字>/SKILL.md`：
   - frontmatter 的 `description` 写清楚“什么时候该用它”（用户会怎么说），这是其他会话发现它的唯一依据；
   - 正文写最短的用法、前提条件、注意事项，细节指向 `~/tools/<名字>/README.md`。
4. 在 `~/tools/README.md` 登记表里加一行。
5. 在 `~/tools` 里 `git add` 并提交（提交说明用中文写清改了什么）。
6. 运行 `skills-sync` 发布到用户的 GitHub 公开仓库 Sylvan-Luo/sylvan（会自动脱敏+隐私扫描，没通过就按提示处理）。
   工具里新出现的私人信息（好友名、学号、电脑名等）先加进 `~/.config/skills-sync/scrub.tsv`。不想公开的写进 `~/tools/skills-sync/exclude.txt`。
7. 做完告诉用户：工具叫什么、怎么用、新会话里怎么触发它、GitHub 上的位置。

## 改一个工具
改代码 → 更新它的 README 和 SKILL.md（用法变了的话）→ 登记表状态 → git 提交 → `skills-sync`。

## 原则
- 运行在哪：要用用户电脑上的东西（微信、浏览器、文件）就经 `tsx sh mac` / pcctl / pcweb；只在 mini 上就够的放 mini。
- 对外的动作（发消息、发邮件、提交表单、付款）必须有确认或白名单，默认先“只起草不发送”，用户明确同意后才放开。
- 账号、密码、口令不写进代码和仓库；需要时让用户自己在对应程序里登录。
- 工具要能在“网页会话台”和“命令窗口”两种会话里都用。
