# wechat

有人**私聊**你的微信时，在「Claude 会话台」网页里提醒你（右上角弹卡片，侧栏有「微信」状态条）；
你说「给 X 发 Y」时，Claude 经你的 Windows 笔记本上的微信替你发出去。**群聊一律不提醒、不发送。**

## 怎么工作的

微信 4.2（Weixin.exe）对这个账号不开放控件树（UI Automation 读不到；讲述人的办法对这种账号也已经失效），
所以只能用**截图 + OCR**：

- 笔记本上：`win/wxagent.py loop` 常驻（pythonw，无窗口），每 4 秒用 PrintWindow 截一次微信主窗口，
  按头像找出会话列表的每一行，用 RapidOCR 只识别文字行（约 20 ms/行，没变化的行直接用缓存），
  找红色未读角标，判断私聊还是群聊，把新的私聊消息写进 `feed.json`。
- mini 上：LaunchAgent `com.user.wechat-watch` 跑 `wx watch`，每 8 秒经 tsx 取一次 `feed.json`，
  新提醒追加到 `~/.local/state/wechat/events.jsonl`，并写 `~/claude-ui/static/wechat-feed.json` 给网页用；
  笔记本上的进程没在跑（开机后、被关掉）时，它会自动拉起来。
- 网页：`~/claude-ui/static/wechat.js`（index.html、tasks.html 各引用一行），每 5 秒读 feed，
  侧栏「微信：…」状态条、红色角标、右上角弹卡片；页面在后台时还会发浏览器通知（点一下状态条可以授权）。
  抽屉里每条提醒有「让 Claude 读全文」「让 Claude 帮我回」两个按钮，会把一句话填进当前会话的输入框（不会自动发）。

## 用法（mini 上）

```
wx status                 监看状态、当前未读的私聊
wx inbox [N]              最近 N 条私聊提醒
wx send 名字 内容 --dry    只在输入框里试填、截图、清空，不发送
wx send 名字 内容          发送（先给用户看收件人和原文，用户确认后才执行）
wx read 名字              打开该私聊，读出屏幕上最近的消息（会标成已读）
wx scan                   立刻读一次会话列表，打印每行识别结果（调试）
wx selftest               塞一条假的测试提醒，检查网页提示
wx autoreopen on|off      微信被关到托盘/最小化时是否自动打开（默认 on）
wx hide | show            托盘模式：微信挪到屏幕外（照常提醒）/ 挪回来
wx start | stop           启动 / 停止笔记本上的识别进程（start 会先同步脚本）
wx install | uninstall    安装 / 卸载 mini 上的 LaunchAgent（uninstall 也会停笔记本上的进程）
wx private add 名字        把某个会话强制当私聊（比如开了免打扰的好友、被误判成群的好友）
wx groups add 名字         强制当群聊（被误判成私聊的群）
wx ignore add 名字         不提醒（add 换成 del 即删除）
```

`wx` 的完整路径是 `~/tools/wechat/wx`。

## 发送的流程和保护

1. 把微信切到前台（约 2～3 秒），点会话列表上方的放大镜，粘贴名字；
2. 在搜索弹窗里只接受「联系人 / 功能 / 最常使用」分区里**名字完全一致**的一项（「群聊」分区的不点）；
3. 打开后核对聊天标题等于名字、标题不带「(人数)」、会话列表里这一行不是群（拼图头像 / 免打扰 / 带发言人前缀），
   任何一步对不上就停下，不发；
4. 点输入框、粘贴内容、回车；截图核对聊天区里出现了这条内容（`verified`），再把前台还给原来的窗口。
   截图存在笔记本 `%LOCALAPPDATA%\ClaudeWx\last_send.png`。

## 依赖和前提

- 笔记本（mac1，<LAPTOP>）：Python 3.10 + 用户级 pip 包 `rapidocr_onnxruntime pywin32 pillow numpy`
  （另外装过 `uiautomation winocr windows-capture`，试验用，现在没用到）。代码在 `%LOCALAPPDATA%\ClaudeWx`，
  由 `wx` 自动同步（按内容哈希），不要直接改那边。
- **微信主窗口要“打开着”**才读得到（关到托盘时 Qt 不画内容，截图是一片白）。工具会自己处理：
  - 被 × 关到托盘超过 10 秒：在你键鼠空闲 ≥3 秒时，用 `Shell_NotifyIconGetRect` 找到右下角托盘里的微信图标
    （收在「^」里就先点开「^」），像用户一样点一下把微信打开，然后马上把焦点还给原来的窗口，进入**托盘模式**：
    窗口挪到所有屏幕外面、去掉任务栏按钮（ITaskbarList.DeleteTab），原位置记在笔记本 `hidden.json`。
    用户看来微信就在托盘里，但它照常绘制，照样能读。每分钟最多试一次。
  - 托盘模式下用户点托盘图标（或 Alt+Tab 切过去）→ 后台线程 0.15 秒内发现微信成了前台，挪回原位置、加回任务栏按钮。
  - 发消息 / 读消息：先挪回屏幕上（点击要真实坐标），做完把焦点还回去、再藏回去；期间写 `busy.lock`，后台识别暂停。
  - `wx hide` 手动进入托盘模式，`wx show` 挪回来；`wx stop` / `wx uninstall` 会先挪回来（免得没人管时点托盘看不到微信）。
    `config.json` 里 `tray_mode=false` 则改为放到最底层而不是屏幕外。
  - 最小化：先把“还原位置”改到屏幕外再不激活地还原（屏幕上最多露 ~5 ms），任务栏按钮保留；
    用户点任务栏按钮时挪回原位置、原大小。
  - **用户自己打开着的窗口一概不动**（2026-11-25 用户要求）：不滚动列表、不改大小、不放最底层；
    窗口太窄（会话列表收起）时只报 `compact`。拉高 / 拉宽 / 滚回顶部都只在托盘模式（屏幕外）下做，挪回来时恢复原大小。
  - 不想要自动打开：`wx autoreopen off`（存在笔记本的 config.json）。
  - 试过但不行的办法：给托盘消息窗口发回调消息、Ctrl+Alt+W 快捷键、ShowWindow 还原（窗口出来了但内容空白）、
    再运行一次 Weixin.exe（会多开出一个新的登录窗口，别这么做）。
- mini 和笔记本之间靠会话台的转发通道（桌面上的「Claude 会话台.cmd」开着）或任一 ClaudeHub 命令窗口。

## 已知限制

- 只看会话列表**可见部分**。托盘模式下：窗口拉到屏幕工作区高度；左侧「聊天」图标上有未读、可见范围里却没有
  带数字的未读时，后台发滚轮消息把列表滚回顶部再读。用户自己开着微信时不动它，
  连续两次找不到（且用户没在用微信）才提醒「列表里没看到」。
- 预览是列表里那一行（被微信截断的），要全文用 `wx read`（会把那个会话标成已读）。
- 群聊判断是启发式：拼图头像、免打扰（预览行最右边的铃铛：约 10 逻辑像素宽、和前面文字隔开一段空白）、预览带「某某:」前缀。开了免打扰的好友默认不提醒（`wx private add` 修正）；
  预览带冒号的私聊消息会标成「可能是群」但照样提醒。
- 当前正打开着的私聊来了新消息：没有红点，靠预览变化 + 最后一个气泡不是绿色（不是自己发的）来判断。
- 名字被微信截断（列表太窄，显示「德...」）时提醒里的名字也是截断的。
- 微信版本更新、改界面后可能要调坐标/颜色（`wxagent.py` 里的 `Layout`、`avatar_rows`、`red_clusters`）。

## 注意

- 用 UI 自动化给别人发消息有被腾讯限制账号的风险：只在用户明确要求时发，频率要低，不群发、不加好友。
- 每次发送前先把「收件人 + 原文」给用户确认（用户 2026-11-25 选的规则：每次确认）。
- 不注入微信、不读数据库、不取任何登录凭证。
